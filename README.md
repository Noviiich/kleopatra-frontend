# Клеопатра

Адаптивный frontend парикмахерской в Орле. React, TypeScript и Vite. Дизайн в тёплой молочной и оливковой палитре, локальные шрифты, собственная редакционная фотосерия.

## Запуск

```bash
npm ci
npm run dev
```

Сайт: http://localhost:5173. Требуется Node.js 22+.

```bash
npm run build      # проверка TypeScript и production-сборка в dist/
npm run preview    # локальный просмотр production-сборки
npm run test:e2e   # браузерные тесты desktop/mobile и axe
```

Перед первым запуском тестов установите браузер: `npx playwright install chromium`.

## Что реализовано

- Адаптивная страница: главный экран, интерактивное меню услуг, философия, фильтрация образов, FAQ, контакты и маршрут.
- Мобильное меню и фиксированная кнопка записи после первого экрана.
- Форма записи: услуга → имя, желаемая дата и время → просмотр заявки и отправка SMS.
- Нативные модальные окна с фокусом, Escape и блокировкой фонового контента; поддержка reduced motion.
- Локальные WebP-изображения, адаптивный hero, lazy loading, загрузка формы отдельным JS-чанком.
- Локальные шрифты Manrope и Cormorant Garamond с кириллицей.

## Проверка качества

Локальный замер production-сборки в Lighthouse, мобильный профиль: **Performance 96**, **Accessibility 100**, **Best Practices 100**, **SEO 100**. LCP — 2,4 с, TBT — 50 мс, CLS — 0,001. Результат на опубликованном сайте зависит также от хостинга и устройства.

Браузерные проверки охватывают запись, валидацию, SMS-ссылку, возврат фокуса, фильтры, FAQ, контакты, изображения, мобильное меню и доступность WCAG A/AA. Компоновка дополнительно проверена на ширинах 320, 375, 390, 768, 1024 и 1440 px.

## Запись и реальные данные

Контакты находятся в `src/data.ts`: **+7 (910) 266-48-23**, **г. Орёл, ул. Раздольная, д. 82Б**.

Форма **не создаёт бронирование на сервере**. Она составляет сообщение и открывает SMS-приложение посетителя по ссылке `sms:`. Посетитель отправляет сообщение самостоятельно, затем салон подтверждает запись. На компьютере доступны копирование заявки и телефон. Нет фиктивных свободных слотов, автоматического подтверждения, хранения персональных данных или скрытого сетевого запроса. Поддержка SMS-ссылок зависит от устройства и установленного приложения.

Фактический прайс, расписание и список услуг владельцем пока не предоставлены. Цены не выдуманы; описания услуг являются предложенным контентом и редактируются в `src/data.ts`. Перед публичным запуском подтвердите перечень услуг. Для автоматической онлайн-записи потребуется подключить реальный провайдер бронирования или backend вместо SMS в `src/components/Booking.tsx`.

Сгенерированные изображения в `public/images/` — визуальная концепция и подборка для вдохновения, не фотографии реального интерьера и работ. На странице есть соответствующие пояснения. Использован встроенный `image_gen`; промпты сохранены в `docs/image-prompts.json`. Перед запуском можно заменить изображения реальными фотографиями с сохранением имён файлов.

## Публикация

Workflow находится в `.github/workflows/deploy.yml`. Он запускается на push в основную ветку, собирает сайт и синхронизирует `dist/` на сервер по SSH. Pull request проходят проверки, но не публикуются. Workflow можно запустить вручную через **Actions → Deploy to server → Run workflow**.

### GitHub Secrets

Добавьте секреты репозитория в **Settings → Secrets and variables → Actions → New repository secret**:

| Имя | Значение |
| --- | --- |
| `SSH_HOST` | IP-адрес или имя сервера |
| `SSH_PORT` | SSH-порт, обычно `22`; если секрет не задан, используется `22` |
| `SSH_USER` | Пользователь SSH, у которого есть доступ к каталогу сайта |
| `SSH_PRIVATE_KEY` | Приватный SSH-ключ этого пользователя целиком, включая строки `BEGIN` и `END` |
| `SSH_KNOWN_HOSTS` | Строка(и) ключа сервера для `known_hosts`, с портом, если он нестандартный |
| `SSH_TARGET_DIR` | Абсолютный путь к корню сайта, например `/var/www/kleopatra` |

Публичную часть ключа из `SSH_PRIVATE_KEY` добавьте на сервер в `~/.ssh/authorized_keys` пользователя деплоя. Этот пользователь должен иметь право записи в `SSH_TARGET_DIR`; на сервере также должен быть установлен `rsync`. Веб-сервер (например, Nginx или Apache) настройте на раздачу файлов из этой директории.

`SSH_KNOWN_HOSTS` можно получить командой `ssh-keyscan -p 22 -H example.com` (подставьте свой порт и адрес), затем сохранить её вывод как секрет. Перед использованием сверьте отпечаток ключа сервера с администратором или панелью хостинга.

Деплой удаляет из `SSH_TARGET_DIR` файлы, которых больше нет в новой сборке. Укажите отдельный каталог сайта, а не общую директорию с другими данными. Сайт собирается для корня домена; если он должен открываться в подкаталоге, сначала задайте нужный `VITE_BASE_PATH` в workflow.
